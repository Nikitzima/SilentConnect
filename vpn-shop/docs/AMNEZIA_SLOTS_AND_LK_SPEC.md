> **Статус:** Утверждено к реализации (Решение зафиксировано 18 сентября 2026)  
> **Тип:** Product & Engineering Specification (Финал)  
> **Связанные документы:** `DEVICE_SLOTS_ARCHITECTURE_RFC.md`

## 1. Стратегическое решение: Прагматичный подход к лимитам

По итогам архитектурного ресерча и анализа сценариев использования принято решение: **не вводить тяжелых распределенных систем межсерверной слежки (cross-node session arbiters)**.

### Обоснование решения:
1. **Фактор домашнего NAT (Wi-Fi):** В любой семье все устройства (телефоны, ПК, планшеты, ТВ) выходят в сеть через один домашний роутер с **одним общим внешним IP**. Никакой лимитер не отличит несколько домашних устройств от одного.
2. **Сплит-туннелирование (`split-ru`):** 80% трафика (Кинопоиск, Госуслуги, банки, маркетплейсы, VK, RuTube) отсекается локально и вообще не грузит зарубежные серверы.
3. **User-Friendly репутация:** Сервис сохраняет максимальное дружелюбие к пользователю без ложных банов при переключении сетей (Wi-Fi ↔ LTE).
4. **Разделение задач:**
   * **VLESS / Happ / Sing-box / Clash:** Остаётся в текущем свободном виде — одна универсальная ссылка содержит все серверы (NL, PL, FI) с авто-переключением.
   * **AmneziaWG:** Управляется через новую **систему слотов в ЛК**, решая реальную техническую проблему конфликта ключей WireGuard.

## 2. Архитектура модуля Слотов AmneziaWG

Пользователь в Личном Кабинете (`sub.example.com`) получает управление слотами для AmneziaWG:

```
┌────────────────────────────────────────────────────────────────────────┐
│               ВЫДЕЛЕННЫЕ СЛОТЫ AMNEZIA VPN / WG 3.1                    │
│                      (Занято: 2 из 3 слотов)                           │
├────────────────────────────────────────────────────────────────────────┤
│ 📱 [ iPhone 15 Pro ✏️ ]                                    🟢 Активен  │
│    Сервер: 🇵🇱 Польша (Пинг: 34 мс)                                     │
│    [ 📥 Скачать .conf ]  [ 📱 QR-код ]  [ 🔄 Сменить страну ] [ 🗑️ ]    │
├────────────────────────────────────────────────────────────────────────┤
│ 💻 [ Рабочий ноут ✏️ ]                                    🟢 Активен  │
│    Сервер: 🇳🇱 Нидерланды (Пинг: 48 мс)                                 │
│    [ 📥 Скачать .conf ]  [ 📱 QR-код ]  [ 🔄 Сменить страну ] [ 🗑️ ]    │
├────────────────────────────────────────────────────────────────────────┤
│ ⚪ Слот 3: [ Свободный слот ]                                           │
│    [ ➕ Создать устройство для Amnezia ]                               │
└────────────────────────────────────────────────────────────────────────┘
```

### Ключевые параметры функционала:
* **Лимит слотов:** Соответствует купленному тарифу пользователя (`device_limit`: 3, 6 или 9 слотов).
* **Кастомное имя девайса:** Инлайн-редактирование прямо в строке слота (валидация: от 1 до 16 символов, безопасная фильтрация спецсимволов).
* **Говорящее имя файла:** При скачивании файл отдаётся с именем:  
  `SilentConnect_<ИмяУстройства>_<Сервер>.conf` (например: `SilentConnect_iPhone_15_PL.conf`).
* **Модальное окно QR-кода:** Встроенная генерация QR-кода в браузере (SVG/Canvas) для сканирования камерой из приложения Amnezia на смартфоне.

## 3. Фича: In-Browser Ping Probe (Замер пинга до серверов)

Поскольку конфиг AmneziaWG привязан к конкретному серверу, при нажатии на **«➕ Создать устройство»** или **«🔄 Сменить страну»** открывается модальное окно с интерактивным замером пинга.

### Механика работы:
1. JavaScript в браузере клиента выполняет 3 быстрых последовательных HTTP HEAD/Fetch запроса с замером задержки (RTT) до каждого сервера:
   * `https://edge.example.com/ping` (Нидерланды)
   * `https://pl.example.com/ping` (Польша)
   * `https://fi.example.com/ping` (Финляндия)
2. Отбрасывается первый "холодный" RTT (TCP handshake overhead), берется медиана 2-го и 3-го запросов.
3. Карточки стран в окне визуально ранжируются:
   * 🇵🇱 **Польша:** `34 мс` — 🟢 **Рекомендуется (минимальная задержка)**
   * 🇳🇱 **Нидерланды:** `48 мс` — 🟢 **Отлично**
   * 🇫🇮 **Финляндия:** `62 мс` — 🟡 **Запасной**
4. Пользователь выбирает локацию в один клик, вводит имя (до 16 знаков) и нажимает «Подтвердить».

## 4. Жизненный цикл и безопасность (Zero-Abuse)

### Мгновенный сброс старого пира (Live Drop):
* Если пользователь нажимает **«🗑️ Удалить»** или меняет страну в слоте:
  1. На сервере старой страны внутри Docker контейнера мгновенно выполняется:
     `awg set awg0 peer <публичный_ключ> remove`
  2. Блок пира вырезается из `awg0.conf`.
  3. Внутренний туннельный IP (`10.8.1.X`) освобождается и возвращается в пул.
  4. Старый файл на устройстве пользователя **моментально перестаёт работать**.
  5. Слот освобождается в ЛК, пользователь может создать новый.

### Заморозка при неоплате:
* При окончании срока подписки:
  - Пиры отключаются в live-памяти контейнера (`awg set ... remove`), но сохраняются в базе данных `vpn_shop.db`.
  - При оплате продления: мгновенная разморозка (пользователю **не нужно** заново настраивать Amnezia на своих гаджетах).
  - При отсутствии оплаты более 14 дней: полная утилизация и удаление из базы.

## 5. План реализации по компонентам

### 1. База данных (`vpn_shop.db`)
Таблица `awg_peers` мигрируется на поддержку слотов:
```sql
CREATE TABLE IF NOT EXISTS awg_peers_v3 (
    sub_id          TEXT NOT NULL,
    server_code     TEXT NOT NULL DEFAULT 'nl',
    slot_id         INTEGER NOT NULL DEFAULT 1,
    device_name     TEXT NOT NULL DEFAULT 'Устройство 1',
    private_key     TEXT NOT NULL,
    public_key      TEXT NOT NULL,
    preshared_key   TEXT NOT NULL,
    tunnel_ip       TEXT NOT NULL,
    created_at      TEXT NOT NULL,
    period_start    TEXT NOT NULL,
    bytes_used      INTEGER NOT NULL DEFAULT 0,
    last_rx         INTEGER NOT NULL DEFAULT 0,
    last_tx         INTEGER NOT NULL DEFAULT 0,
    active          INTEGER NOT NULL DEFAULT 1,
    inactive_reason TEXT,
    PRIMARY KEY (sub_id, server_code, slot_id)
);
```

### 2. Бэкенд управления (`awg_manager.py`)
- Добавление параметров `slot_id` и `device_name` во все методы (`create_peer`, `get_peer`, `build_conf`, `remove_peer`).
- Метод `rename_device(sub_id, server_code, slot_id, new_name)` (валидация длины `<= 16` символов).
- Метод получения активных слотов подписки: `list_slots(sub_id)`.

### 3. Веб-интерфейс каталога (`subjson-service/app.py`)
- Легковесный эндпоинт `/ping` (возвращает `204 No Content` для нулевого оверхенда замера задержки).
- API эндпоинты управления слотами:
  - `GET /api/awg/<sub_id>/slots` — список слотов пользователя с их статусами и именами.
  - `POST /api/awg/<sub_id>/slots/create` — создание слота (сервер, имя).
  - `POST /api/awg/<sub_id>/slots/<slot_id>/rename` — переименование устройства.
  - `POST /api/awg/<sub_id>/slots/<slot_id>/delete` — удаление слота с live-сбросом.
  - `GET /my-secret-sub/awg/<sub_id>/slot/<slot_id>/conf` — скачивание именованного `.conf`.
- UI-компоненты:
  - Блок слотов Amnezia с адаптивным дизайном под мобильные экраны.
  - JS-модуль замера RTT с индикаторами качества связи.
  - Модальное окно QR-кода.

### 4. Синхронизация между нодами (`scripts/failback_merge.py`)
- Обновление функции `merge_awg_peers` для слияния записей с составным ключом `(sub_id, server_code, slot_id)`.
