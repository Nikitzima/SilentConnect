# SilentConnect Edge Failover & Zero-Cost Serverless Architecture

## 1. Введение и Проблема
Прямой доступ к зарубежным серверам из сетей РФ подвержен регулярным блокировкам и ТСПУ-замедлениям:
- Прямые запросы по IP или доменам европейских дата-центров (Aeza NL, Hetzner FI, Aeza PL) могут сталкиваться с `Connection Refused` или таймаутами `WinError 10060`.
- В случае аварии на основном узле (NL) клиенты теряли доступ к Личному кабинету (`sub.<domain>.net`), витрине магазина (`<domain>.net`) и страницам оплаты заказов (`/order/...`), а входящие вебхуки эквайринга Platega не доставлялись.

## 2. Архитектурное Решение
Для гарантированной доступности развернута трехуровневая гибридная топология:

1. **Cloudflare DNS Layer (DNS-Only ⚪)**:
   - Внешний DNS управляется Cloudflare в режиме `DNS-Only` (Proxy Status: DNS only, оранжевое облако выключено) с TTL 120 сек.
   - **Apex CNAME Flattening**: Для корневого домена `<domain>.net` используется технология Cloudflare CNAME Flattening. В авторитетных NS-ответах корень отдается как Anycast A-запись шлюза Yandex Cloud (`203.0.113.10`), что исключает конфликт со стандартными MX/SPF/DKIM/DMARC записями почты.
   - Поддомены `sub.<domain>.net` и `www.<domain>.net` направлены CNAME-записями на единый API Gateway Yandex Cloud.

2. **Yandex Cloud Serverless Edge Proxy**:
   - **API Gateway (`sub-proxy-gateway`)**: Точка входа Anycast IP с автоматической терминацией SSL-сертификатов Let's Encrypt для всех трех доменов (`<domain>.net`, `www.<domain>.net`, `sub.<domain>.net`).
   - **Cloud Functions (`sub-proxy`)**: Высокопроизводительная функция на Node.js 22 (256 MB RAM, 5s timeout).
   - **Failover Logic (NL ➔ PL ➔ FI)**:
     * Запрос сначала отправляется на основной узел NL (`https://edge.<domain>.net`).
     * Таймаут ожидания составляет 3.5 секунды.
     * При сбое соединения, таймауте или ответах HTTP 502–504 запрос немедленно и прозрачно перенаправляется на резервный узел PL (`https://pl.<domain>.net`), а при его недоступности — на узел FI (`https://fi.<domain>.net`).

3. **Backend Nodes Parity (Caddy + Services)**:
   - На обоих серверах (NL и PL) развернуты идентичные сервисы:
     * `vpn-shop-web.service` (порт 3090) — витрина, ЛК по почте, заказы `/order/*`, вебхук эквайринга `/api/payment/*`.
     * `subjson-service.service` (порт 3088) — выдача подписок, smart-селектор конфигураций, ЛК подписки `/my-secret-sub/import/*`.
   - В конфигурации Caddy (`/etc/caddy/Caddyfile`) настроена маршрутизация по заголовку `X-Forwarded-Host: ^(www\.)?<domain>\.net$` и путям `/order/*`, `/api/payment/*` на порт 3090, а остальных запросов — на порт 3088.

## 3. Финансовый Аудит: Гарантия Нулевых Расходов (Zero Cost)
Архитектура спроектирована с нулевыми эксплуатационными затратами:
- **Compute Instances**: 0 (виртуальные серверы не арендуются).
- **Compute Disks**: 0 (дисковые накопители отсутствуют).
- **Serverless Free Tier**:
  * Cloud Functions: первые 1 000 000 вызовов в месяц — бесплатно.
  * API Gateway: первые 100 000 вызовов в месяц — бесплатно.
  * Certificate Manager: хранение и использование сертификатов Let's Encrypt — бесплатно.
- Месячный бюджет Yandex Cloud на этот компонент составляет **0 рублей**.

## 5. Аварийный режим (Emergency Stubs)
Если все три дата-центра (NL, PL, FI) окажутся одновременно недоступны, функция не падает с ошибкой 500/502, а возвращает валидные сервисные заглушки:
- Для клиентов sing-box: JSON с блокирующими outbound-правилами и текстовым статусом «Серверы на плановом обновлении».
- Для клиентов Happ / V2Ray: JSON-профиль с информационным баннером и ссылкой на службу поддержки.
- Для браузеров: аккуратную страницу с сообщением о технических работах.
Это предотвращает панику пользователей и случайное удаление профилей из приложений.
